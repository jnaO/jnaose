# Design system

Two routes sharing one scroll-snap scene: one line of copy (or one project) per screen, scrolling over a fixed photo, orange ink inverted by blend mode. `/` sits on a B/W photo, `/work` on a colour one.

## Tokens
- Ink `--text-color: orange`; hover/focus `--highlight-color: #FFFFFF` (`src/app/globals.scss`). Dark-mode block does not override either.
- Accent `gold`: stroke of the header logo only (`Logo` config).
- Font: Rajdhani 400 via `next/font`, class on `<body>`, var `--font-rajdhani`. Body copy 1rem / 1.5.
- Gutter: `max(env(safe-area-inset-*), 1rem)`.
- `--top-cover-height` (`:root` in `globals.scss`): `TopCover` height and the JnaoLogo stage's `pointer: coarse` top offset.
- Logo block: `--logo-width`, `--logo-block` (= 1.5rem + width × `--logo-ratio`).
- Art ratios, inline on `<html>` from the art modules (`ART_RATIOS` in `layout.tsx`): `--logo-ratio` (h / w), `--ratio-home`, `--ratio-work` (W / H of each spine word).
- Spine: `--spine-band` (rendered height H of a word's viewBox = the band's width once rotated; `clamp(22px, 4.4vh, 33px)`, from 48rem `clamp(27px, 5.75vh, 46px)`: the owner's x-height clamps converted once through the art of the time, never at runtime), `--spine-gap`, `--spine-top`, `--spine-home` / `--spine-work` (band × ratio = each word's length), `--spine-bottom` (top + both lengths + gap).
- `--rail`: right column kept clear of page text (6.25rem, from 48rem 23.75rem); `.segment` and `.project` use it as `padding-right` (`max(env(safe-area-inset-right), var(--rail))`), and it is the MenuWindow canvas width.
- `--ruler-span`: Ruler length from first to last long tick (176px, from 48rem `clamp(176px, 27.2vh, 240px)`). Ruler derives `--ruler-pitch` = `max(44px, span / (count − 1))`, so more segments pack tighter, and `--minor` = pitch / 5.
- Backdrop: `Backdrop` (fixed, `z-index: -1`) — `bg.jpg` as a CSS layer (`.mono`: `cover`, `center left`) plus a `<canvas>` (`.print`) holding the WebGL print of the current page's photo (see Backdrop print). When a page loads in colour, `.still` (server-rendered, CSS-only copy of `paintArt`'s output, fed by `STILL_VARS`) covers the mono photo. `.mono` / `.still` are the clean photos the canvas prints over, shown whenever it holds no print (`painted` false: without WebGL2, on a lost context), so a `/work` reload never shows `bg.jpg`. Over them, under the canvas, `.paper` (flat `PRINT.paper`, server-rendered) covers them until the canvas first prints (see Backdrop print, Load print-in); `@media (scripting: none)` hides it, so without JS the clean photos show. `html` is solid black behind it; iOS Safari 26+ tints both its top and bottom bars from the page's `background-color` (`body`'s if set, else `html`'s), ignoring `theme-color` and background images. Its last child `.blur` (`inset: 0`) has `backdrop-filter: blur(calc(var(--finale-blur, 0) * $blur-max))` (`$blur-max` 24px, top of `backdrop.module.scss`); it is mounted only while `--finale-blur` on `<html>` is above 0 (`useFinaleBlur` in `src/hooks/`, a MutationObserver on `<html>`'s `style`). Trap: with `.blur` mounted, iOS Safari can turn its status bar white until reload. `TopCover` prevents it: Safari 26+ colours the status bar from the `background-color` of the topmost fixed layer 4px below the top edge (sampled at `opacity: 0`, not when `display: none`), so `TopCover` must stay displayed, have a solid `background-color` and be deeper than 4px. Only the footer finale writes `--finale-blur`. Trap: do not leave a `backdrop-filter` layer over the canvas at rest — on iOS WebKit it does not repaint when the canvas redraws, so the print freezes on screen until something else forces a repaint. Trap: do not blur `.backdrop` itself with `filter` — a filter samples transparent pixels past the element's edge, so the edges go see-through and the `html` background shows through as a haze. `backdrop-filter` samples past its edges from its own edge pixels.

## Blend model
`mix-blend-mode: difference` on `.segment`, `.title`, `.link`, `Logo` path, `JnaoLogo` `.stage`. Orange reads differently over sky vs ground — this contrast shift IS the look. Any new foreground element joins it by applying `difference`; a solid background on an ancestor breaks the effect.
- **Ink / window layers (menus):** a photo can never live inside a `difference` element (it would be differenced too, and a fixed element's children blend only inside it). So each menu mark has two layers: the **ink layer** (the fixed `SiteMenu` / `Ruler` nav, `difference`, `ui-chrome`: outlines, ticks, numbers, the needle, every link) and the **window layer** (`MenuWindow`: one fixed `<canvas>` over the rail, normal blend, `ui-chrome`, `pointer-events: none`, `aria-hidden`), which paints the other page's photo clipped to the spine words. The Ruler's needle is ink only (hollow). `ui-chrome` goes on each fixed UI root, never on an ancestor of a blended element.
- **Paint order:** `MenuWindow` renders after `TopCover` and **before `<main>`** in `layout.tsx`, with `z-index: auto`: both ink navs (the Ruler inside `<main>`, SiteMenu after it) paint over it in DOM order, so their borders invert over the photo, and it stays under TopCover's 1000.
- **Carrier contract:** CSS drives every mark; MenuWindow only reads geometry. Carriers are invisible elements inside a nav: `data-window="word"` + `data-word="home|work"` on the spine svg, with a sibling `data-window-wipe` (the fill extent); A zero-size carrier paints nothing. Each repaint reads every carrier's `getBoundingClientRect()`; the word's path matrix comes from its svg rect and `words.ts` (`wordMatrix`), never `getScreenCTM`. Mask → `source-in` the window printer's offscreen canvas (see Mirror). Without a print (no WebGL2, lost context): mask → `source-in` mono `bg.jpg` at `cover` + `center left` of the live viewport (as `.mono`) → on home (`frame.time` 0) `source-atop` `frame.art` at the live viewport size. MenuWindow repaints on every `backdropFrame` publish (synchronously, inside the Backdrop's frame), on resize, and on bubbling transition/animation events, then keeps a rAF loop only while a carrier's nav reports a running animation (`getAnimations({ subtree: true })`); idle, it does no work.
- **UI fade contract:** the footer finale fades out every element carrying the global class `ui-chrome` (`UI_CHROME` in `src/constants.ts`): currently `h1.title`, the `SiteMenu` nav, the `Ruler` nav and the `MenuWindow` canvas. `globals.scss` gives `.ui-chrome { opacity: var(--ui-opacity, 1) }` and `html[data-finale] .ui-chrome { pointer-events: none }`; the finale timeline tweens `--ui-opacity` 1 → 0 on `<html>` during the in phase, and the trigger toggles `data-finale` on `<html>`. Any new fixed or sticky UI must carry `ui-chrome` on the element that itself has `mix-blend-mode` — never on an ancestor (opacity < 1 there isolates the blend group and the UI changes colour mid-fade). The `Backdrop` does not fade. Keyboard focus of faded links is not managed.

## Scroll model
- `layout.tsx` owns the scroller: `<main id={SCROLLER_ID} class=.main>` (100vh, `overflow-y: scroll`, `scroll-snap-type: y mandatory`) → `.padder` → sticky `h1.title` Logo → page `{children}` → `footer.footer` JnaoLogo. The document itself does not scroll.
- Pages render segments only. Home: `<section className={styles.segment}>` (100% of the scroller, snap `end`, content bottom-left). Work: `.project` (100% of the scroller, snap `end`).
- `.footer` is `position: relative; height: 200%; pointer-events: none` (two scroller heights; positioned and later in `<main>` than the fixed `Ruler`, so it paints over the Ruler and would take its clicks) with **no** snap-align of its own — a 200% snap area would allow free scrolling inside it. `JnaoLogo` renders into it: two absolute `pointer-events: none` snap markers (`.footerSnap` at `top: 0`, `.runwaySnap` at `top: 50%`, each `height: 50%`, snap `end`) and the `<h2>` stage (`position: sticky; top: 0; height: 50%`, full width, `pointer-events: none`; on `pointer: coarse` it is `top: var(--top-cover-height); height: calc(50% - var(--top-cover-height))`, so it starts where the `TopCover` strip ends). Trap: iOS Safari tints its status bar from a sticky element pinned at the top edge, and the stage would turn it white until reload; `TopCover` is the layer above it at Safari's sample point. The stage stays pinned between the footer snap and the runway snap (= max scroll), so the logo does not move while scrolling between them. `.box` sits in the stage at `left`/`bottom` = gutter.
- `TopCover` (fixed, `top: 0`, full width, `height: var(--top-cover-height)`, `#000`, `opacity: 0`, `z-index: 1000`, not `ui-chrome`): an invisible strip that is always present; it exists only for iOS Safari's status-bar sampling (see Backdrop).
- `SiteMenu`/`Ruler` are `position: fixed` after/inside the scroller; they join the blend because nothing between them and the backdrop creates a stacking context.

## Scene model (page changes)
- `startScene(href, swap)` (`src/hooks/useSceneLink.ts`) — THE page-change routine; `useSceneLink` (menu, `WorkLink`) and `HistoryScenes` (back/forward) both call it. Order: `requestColour` (the print's reveal starts; the spine's wipes move; the current page's Ruler starts its OUT) → in parallel, smooth-scroll to top (`scrollend`, 1s fallback; skipped when already at the top) and `RULER.outMs` (`src/components/Ruler/timing.ts`) → `swap()` (`router.push`/`replace` with `scroll: false`) only once **both** have finished (the Backdrop's scene print-in runs before its reveal and is not waited for, see Backdrop print), even when already at the top → the new page's Ruler plays IN on mount (also on first load). `HistoryScenes` inherits the wait. The new page always starts at the top; nothing scrolls it down.
- Only the segments under the shared logo change; the logo moves purely by scrolling.
- All links into the scene pass `scroll={false}`; Next's own scroll reset would fight the scroller.
- `prefers-reduced-motion` is not consulted anywhere; all motion always runs.

## Backdrop print (`src/components/Backdrop/`)
- Code: `print.ts` = THE print module: `PRINT` (the owner's settings under the prototype's key names, `prototypes/print-raster/index.html`), `TOTAL_MS` (`sweepMs + printMs`, 830) / `LEAVE_SPEED`, `revealTime`, `mirror`, `PRINT_IN` (`sceneMs`, `loadMs`, `coverMs`: the print-in tuning) / `SETTLED_FADE` / `sceneInMs` / `sceneFade` / `loadPress`, `lodBias`, the scroll fade helpers, `Art`/`LANDSCAPE`/`PORTRAIT`/`pickArt`, `loadImage`, `artTop`, `paintArt`, `coverRect`. `printShader.ts` = the GLSL ES 3.00, reduced from the prototype's fragment shader with its function names kept. `printer.ts` = `createPrinter(canvas, { preserveDrawingBuffer?, onLost?, onRestore? })` → `Printer | null` (`setMono`, `setPhoto`, `draw(view, { time, fade, press? })`, `dispose`). `backdropPrint.ts` = `createBackdropPrint(canvas, { onPainted, onUncover })`: the Backdrop's clock, scene and load print-ins, paper-cover rule, redraw rules and publish; `Backdrop.tsx` keeps the React wiring, `.still` vars and markup.
- **The print:** one fragment shader prints a photo in CMYK on newsprint (paper `PRINT.paper`, misregistered C/M/Y plates at 15°/75°/0°, K at 45°, rough edges, mottle, paper grain). Pixel positions are viewport CSS px: `p = uOrigin + (gl_FragCoord.x, uCanvas.y − gl_FragCoord.y) / uDpr`, with the sweep measured against `length(uView)`, so a canvas covering any part of the viewport prints the same pixels the Backdrop would there. Mono `bg.jpg` is placed at `coverRect` (`.mono`); the colour photo is `paintArt`'s canvas mapped to the full live viewport (stretched from its `w×h` snapshot, as `.still`). Tone is sampled at a mip level `lodBias(texels per CSS px)` = `PRINT.soft + log2(…)` per texture (mono: `naturalWidth / cover width`; colour: `canvas.width / W`), so the tone blur is the same at every DPR. At fade 1 the shader outputs the clean photos. Last, `uPress` (0 → 1) dissolves the result in from flat `uPaper` through the same screen; at 0 the canvas is exactly `.paper`'s colour, at 1 (the default for any printer whose caller leaves `press` out, e.g. MenuWindow) it has no effect.
- **Both pages rest printed.** `time` is the page's reveal clock: 0 prints home's mono photo, `TOTAL_MS` the colour photo. The sweep runs from the top-left; as it passes, each pixel re-sizes the same dots from one image to the other over `printMs`. A colour change runs `time` towards `colour ? TOTAL_MS : 0` from wherever it is (`revealTime`: 1 ms of clock per ms entering, `LEAVE_SPEED` leaving), so a reversal mid-reveal does not jump. First mount and an unchanged colour settle without animating.
- **One clock:** every Backdrop draw publishes `{ art, time, fade, w, h }` to `src/lib/backdropFrame.ts` (`w`/`h` = the snapshot `art` was painted at). Any other layer that shows the print mirrors this store instead of running its own timer.
- **Scroll fade:** "dissolve through screen": the clean photo floods in through a screen (`angle` + 0.3 rad) as `fade` runs 0 → 1. `fade = scrollFade(scrollTop, end)` = smoothstep of `scrollTop / end`, 0 at scroll 0 and 1 at `end` = the snap rest (`restScrollTop`) of the scroller's `FADE_END_SEGMENT`-th (1) direct `:scope > section` (the last if there are fewer; fade 0 with none). It is read on every draw, including reveal ticks, so `startScene`'s scroll to the top prints the photo again while it sweeps. Published in the frame.
- **Scene print-in:** an animated reveal (a colour change from a menu click or back/forward, both via `startScene` → `requestColour`) first runs the shown fade from its current value `from` to 0, as if already at the top, over `sceneInMs(from)` = `from × PRINT_IN.sceneMs` (300 at fade 1; 0 at fade 0, so the reveal starts at once); only then does `time` start (`revealTime(…, elapsed − sceneInMs(from))`). The shown fade is `sceneFade(from, elapsed, readFade())` = `min(ceiling, readFade())`: the ceiling falls linearly to 0 and stays there, so the smooth scroll to the top can lower the fade sooner but never raise it; once the ceiling is 0 and `readFade()` ≤ `SETTLED_FADE` (scroll at the top, before or after the swap: both pages read 0 there) the hold lets go and `readFade()` shows alone, without a jump. The shown (held) fade is what is drawn and published, so MenuWindow follows it. The reveal's rAF loop runs until both the print-in and the clock are done. A reversal mid-scene starts a new print-in from the fade shown at that moment. `startScene`'s swap rule is unchanged: the hold does not depend on the route, so the swap needs no extra wait. Trap: if the user interrupts the smooth scroll and then scrolls down, the hold keeps the fade at 0 until the scroll next returns to the top.
- **Load print-in:** `.paper` (React state `paper`, initially true, so it is the server-rendered state) goes once `onUncover` fires, which happens once: at the canvas's first successful draw (drawn at `press` 0 = flat paper, so the swap is seamless; then `press` runs `loadPress(elapsed)` 0 → 1 over `PRINT_IN.loadMs` on its own rAF loop), at once when `createPrinter` returns null, on a lost context, or after `PRINT_IN.coverMs` without a print (then `press` is 1, so a late first print pops in over the clean photos). `Backdrop` calls `react-dom`'s `preload` for `bg.jpg` and the colour art (`fetchPriority: 'high'`, `media` `(orientation: landscape|portrait)` per art) during render, so the preload links are in the server HTML; `loadImage` then hits the same URLs.
- **Redraws:** reveal ticks, load print-in ticks, scroller `scroll` (passive) and window `resize`, coalesced to rAF. A draw whose `(time, fade, press, W, H, dpr)` match the last is skipped, publish included; `fade` clamps at 1 past segment 2, so nothing redraws under the footer finale's `.blur` (the iOS `backdrop-filter` trap, see Tokens). `printer.draw` also skips GL work when its inputs match its last draw with no upload since. The GL backing store tracks the live viewport (`innerWidth × innerHeight × dpr`), so dots stay round through an iOS toolbar collapse; the colour art is repainted only on a width change (`useViewportWidth`).
- **Fallback:** `createPrinter` returns null without WebGL2 or when the shader fails to compile/link (info log in the console). Then the canvas stays blank, `painted` stays false, `.paper` goes at once, `.mono` / `.still` show the clean photos, and a page change swaps instantly (`time` jumps; frames are still published for MenuWindow). A lost context (`webglcontextlost`, default prevented) sets `painted` false (and uncovers `.paper` if it is still up); on restore the printer rebuilds, re-uploads its retained sources and calls `onRestore`, which redraws.
- **Mirror (`MenuWindow`):** a second printer on an offscreen canvas (`preserveDrawingBuffer: true`) sized to the rail canvas prints the other page's photo with the view `{ W, H, origin: [rail.left, rail.top], dpr }` and the state `{ time: mirror(frame.time), fade: frame.fade }`: page entering colour → the window prints home's photo over `TOTAL_MS`; page leaving at `LEAVE_SPEED` → the window prints the colour photo. Its sweep lines up with the Backdrop's, and it dissolves with the Backdrop's scroll fade. `setPhoto(frame.art)` runs whenever the frame's `art` changes identity; `setMono(bg)` once. Without a print it paints the clean other-page photo (see Blend model, carrier contract).
- Colour = `useSceneColour()` (`src/lib/backdropRequest.ts`) = `requested ?? isColourPath(pathname)`; `requestColour` lets the click start the reveal before the route changes, reset to `null` on every pathname change.
- Colour photo: `forest.jpg` when landscape, `fireweed.jpg` (shifted up by `offset`) when portrait; scaled to viewport width, bottom `FADE` share faded into black. Top edge = `artTop`: shifted up by `offset`, and further on short viewports so the photo's `dark` row (where its left half turns solid black) stays at least `RESERVE_REM` above the viewport bottom, keeping /work project text on black; `.still` repeats the same `min()` in CSS.

## Work page
- Content comes from `src/data/projects.ts`; adding a project = one entry + an icon in `assets/images/projects/`.
- `.icon`/`.text` fade up via `animation-timeline: view()` (`entry 0% → entry 100%`), behind `@supports`.

## Ruler (`src/components/Ruler/`)
- One component on both pages, rendered by each page (so it mounts and unmounts with it): `{ label, items: { id, name? }[] }`. Home: `label="Sections"`, ids from `page.tsx`'s `SECTIONS`, no names. Work: `label="Projects"`, `id = slug`, `name`.
- Rows = a start row, the page's items, an end row; numbered from `00` (`projectNumber(i)`). Start (`00`, id `top`, no element): its rect is `firstScreen` (`current.ts`), the scroller's first screen of content, so it is current and holds the needle at scrollTop 0; click → scroller `scrollTo({ top: 0 })`. End (next number, name `SITE_NAME`): `LOGO_REST_ID` on `JnaoLogo`'s `.footerSnap`, where the logo rests before the finale; the finale then fades the Ruler (UI fade contract). `--count` and the staggers count all rows.
- Current = the row whose segment covers > half the scroller (`current.ts`), else none; `aria-current="location"`. Click → `scrollIntoView({ block: 'end', behavior: 'smooth' })`.
- Layout, right to left: needle | scale (minor-tick `repeating-linear-gradient` + right border line) | long tick, number, name. Rows are `<a href="#id">`, 44px tall, at `--ruler-pitch`; the item count arrives as `--count`, height = `(count − 1) · pitch + 44px`. The scale runs from one `--minor` above the first long tick to one below the last; its gradient (period = pitch) draws four minor ticks per pitch and leaves out the fifth, so each row's long tick IS that scale tick, never an overlay. Long ticks grow from and shrink back to the minor length (`--minor-w`, `tickGrow`/`tickShrink`), never to 0, so the scale never shows a gap. Long tick: rest, hover/focus mid, current longest and 2px with a bold number (Rajdhani is loaded at 400 only, so the bold is synthesised). Names only from 48rem, only for current or hover/focus; the row's `aria-label` is the name.
- Needle: a hollow stroked triangle from `needle.ts`'s `NEEDLE_POINTS`, no window fill; springs along with `translate`, `scale: 0 1` (from its left edge) when there is no current item.
- Placement: from 48rem `top: max(--spine-bottom + gap, 100vh − gutter − height)` (on very short desktops it runs off the bottom rather than over the spine); below, `top: max(--spine-bottom, --logo-block) + gap`.
- **Choreography** (all durations and delays: `RULER` in `Ruler/timing.ts`, passed as inline custom properties — `RULER_VARS` on the nav, `rowVars` per row, `needleVars` — so no duration lives in SCSS; easings do). Staggers are spread over a fixed span (`share` = index / (count − 1)), so `RULER.outMs` does not depend on the item count.
  - IN (on mount, `backwards` fill): the whole nav is uncovered top-down by one linear `clip-path: polygon()` (`uncover`, `--scale-in`; reaches far left so names are not cut). Scale, long ticks (still at minor length, being scale ticks) and needle come with it, never squashed. Each long tick grows (`tickGrow`, width `--minor-w →`, overshoot) `tickLagMs` after the edge reaches its row (`(i + 0.5) / count · scaleMs`, `rowDelays`); each number/name writes out left → right (`clip-path: inset(0 100% 0 0) → inset(0)`) `labelLagMs` after its own tick starts; the needle springs out once the current tick lands.
  - OUT (`.leaving`, `forwards` fill, held until unmount): labels un-write bottom-first; the needle retracts into the scale with its label; ticks shrink back to minor length bottom-first (`tickShrink`); the same clip then closes upwards (`cover` on `.ruler.leaving`), ending at `RULER.outMs` (750ms). Overlap is intended; the owner tunes the numbers.
- `leaving` = `leavesPage(useRequestedColour(), pathname)` (`src/lib/backdropRequest.ts`): a request for the other page's colour, both directions. While leaving, `current` freezes, so the needle does not track the scroll to the top.

## Links
- `.link` (text): inline-flex, 3rem tall, bottom-aligned, `padding-right: 1rem`. Rest: transparent outline + bg. Hover/focus: white text, 1px white outline, 20% white bg. Durations in `.1s` on hover, `.9s/.5s/1.3s` (color/outline/bg) out — asymmetric by design.
- `.listLink` (logo): `@extend .link`, 5rem square, swaps `fill` to highlight on hover. Lives in `ul.list > li.listItem` (flex row, 1rem gap via margin).
- Spine words (`SiteMenu`): each a `next/link` (`scroll={false}`, `useSceneLink`, `aria-label`, `aria-current="page"` from the real pathname) holding an inline svg: viewBox `0 0 H W`, a `<g>` rotation `matrix(0,-1,1,0,0,W)` (`spine.ts` `wordRotation`: word point (u, v) → (v, W − u), reading bottom → top), then the export's own `transform` group. Paths are `currentColor` (white, inverted by the nav's blend) 1.5px outlines with `vector-effect: non-scaling-stroke`. The link pads its sides to a 44px hit target. Filled = the photo window through the wipe carrier, which scales `1 0 → 1 1` from the bottom for the shown word, `:focus-visible`, and `:hover` under `@media (hover: hover)` only (no sticky fill after a tap). The outline group carries an svg `<mask>` (white rect minus a black copy of the word in `.hole`, which scales with the wipe, `transform-box: view-box`, origin bottom), so where the photo fills only the outline's outer half (~0.75px) shows; hover and current look the same. Shown word = `useSceneColour()`, so the fill moves at click time; `aria-current` waits for the route. Focus ring: `2px dashed` white, offset 4px. Never put a CSS transform on the nav, link or svg: MenuWindow builds the word's matrix from the svg's box rect.
- Logo SVGs get their colour from inherited/`var(--text-color)` `fill`, never a hardcoded fill attribute — otherwise hover cannot recolour them.

## SVG conventions
- Always inline JSX components in `src/components/<Name>/<Name>.tsx` + `<name>.module.scss`; no `<img>`. Paths keep their exported `matrix(...)` transforms.
- **Swappable artwork:** art the owner re-exports lives in one TS module as an `SvgArt` (`src/lib/svgArt.ts`: `{ viewBox: [w, h], transform, paths }`), copied verbatim from its `src/assets/images/*.svg` export (the svg stays committed as the source; nothing imports it). Modules: `Logo/art.ts` (`LOGO_ART`, header logo), `SiteMenu/words.ts` (`WORDS.home` / `WORDS.work`, the spine words; SiteMenu draws them, MenuWindow fills them). Layout sizing derives from the viewBox only: `layout.tsx` sets each ratio inline on `<html>` (`ART_RATIOS`: `--logo-ratio` = h / w), and `globals.scss` tokens multiply by it. A new export means editing the module only; never hard-code a viewBox number or a measurement of the current paths outside it. New art with more whitespace in its viewBox renders smaller; that is the contract. Trap: the ratio variables must sit on `<html>`, not `<body>` — `:root` tokens such as `--logo-block` resolve their `var()`s on `<html>` and inherit the result.
- Exception, `JnaoLogo`: each of its 36 paths is its own `<svg>` (CSS 3D transforms do not apply to SVG children). Path data lives in `JnaoLogo/shards.ts` as `{ d, tone, bbox }`; `bbox` is the path's bounding box in the 994×981 viewBox plus ~1 unit padding. Each shard svg uses that bbox as `viewBox`, `preserveAspectRatio="none"`, and `left/top/width/height` = bbox as percentages of 994×981 inside `.box` (`aspect-ratio: 994 / 981`). Changing a path's `d` means re-measuring its bbox.
- `SvgPathWrapper` — THE `<g>` wrapper for stroke-animated logos: carries `transform`, `fillRule=evenodd`, `stroke`, `strokeWidth=0`.
- `useAnimatedLogo(ref, config)` (`src/hooks/useAnimatedLogo.ts`) — THE stroke-pulse animation. Animates every `<path>` under `ref`: `draw 0→1`, strokeWidth `0 → full → 0 → ...extraStrokeWidths → 0`, 100ms stagger per path, random loop delay (4–7s default). Mobile (Bowser) uses `strokeWidthMobile`; IE skipped. Returns `strokeColorAlternative` to pass into `SvgPathWrapper`. Used by `Logo`, `DMBLogo`, `GoksoyraLogo`.
- One-off animations use `createScope({ root })` in a `useEffect` with `scope.revert()` cleanup, targeting a global (non-module) class string, e.g. `'.logo'`, `'.wrapper'`, `'.blink'`.

### Footer finale (`JnaoLogo`)
- Tuning constants: `FINALE` at the top of `src/components/JnaoLogo/finale.ts` (seed, perspective, durations, eases incl. `leaveEase`, stagger, distance, jitter, rotation, depth, fullscreen opacity). Backdrop blur strength: `$blur-max` in `src/components/Backdrop/backdrop.module.scss`. Heartbeat constants: `C` in `JnaoLogo.tsx`. Keep `depthMax` < `perspective`, or shards pass behind the camera.
- Trigger: an `IntersectionObserver` (root = scroller, `threshold: RUNWAY_THRESHOLD` 0.5) on the `.runwaySnap` marker. The first callback only records the side (seeking to the end and starting the orbit if the page is already on the runway). Triggered, not scroll-scrubbed. After that a small state machine in `JnaoLogo.tsx` (`rest` → `flying` → `orbit` → `leaving`) decides what a crossing does:
  - `rest`/`flying`: in → `tl.play()`, out → `tl.reverse()`, both turning around from the current playhead.
  - `orbit` (including the ramp), out: `orbit.pause()` (holds the pose, keeps `data-orbit` and the widened perspective) and `finale.leave(orbit.poses, …)` plays: a paused timeline with `composition: 'none'` (the default `'replace'` would strip the paused `tl`'s tweens on the same shard properties) taking each shard from its live orbit values to its in-phase off-screen pose, and `--ui-opacity`/`--finale-blur` back to 1/0, over `inDuration` with `leaveEase`.
  - `leaving`: in → `leave.reverse()`, out → `leave.play()`. Reversed to its start, the orbit resumes from the kept `s` (speed ramping in again, no jump). Completed forward (every shard off-screen, both variables at rest): `orbit.stop()` then `finale.reverseFromMid()` = `tl.seek(midpoint).reverse()`, so the shipped out-phase reverse and geometry swap play unchanged; state `flying`. The seam swaps shards from their in-phase to their out-phase off-screen pose, both invisible.
  - Resize cancels a running leave (no revert: `tl.revert()` clears everything it and the orbit wrote), rebuilds, and on the runway resumes the orbit from the kept `s`.
- `createFinale()` builds one paused timeline: **out** (each `.shard` tweens `translateX/Y/Z`, `rotateX/Y/Z` from identity to a seeded off-screen pose: direction = viewBox centre → bbox centre + jitter, distance = stage diagonal + shard radius × 1.1–1.5) → label `mid`: `tl.set(box, { left, bottom, width, '--shard-opacity' })` to the contain-fit rect (stage minus the resting gutter, scaled by `FINALE.fullScale`, centred) → **in** (a second seeded pose → identity). Total ≈ 1.1s. From `mid` for `inDuration`, `<html>` also tweens `--ui-opacity` 1 → 0 and `--finale-blur` 0 → 1 (UI fade + backdrop blur); both variables live only in the in-phase, so at `mid` both are at rest.
- Randomness: `utils.createSeededRandom(FINALE.seed)`, created fresh per build and consumed in fixed shard order, so every run and every rebuild produces the same poses.
- `tl.onComplete` fires at both ends (`self.reversed` tells which). At rest after a reverse the timeline is `revert()`ed and rebuilt, which clears every inline transform/geometry it wrote. Resize with a changed stage size also reverts and rebuilds, then seeks to the end if on the runway. The heartbeat runs only at rest: `pulse(false)` pauses it and seeks it to 0 (scale 1) whenever the finale leaves rest (including a load straight onto the runway), and `pulse(true)` resumes it only on the settle at rest or a resize off the runway. No pulse during the fullscreen logo or the orbit.
- The timeline lives outside the `createScope` (it is rebuilt after each round trip); the effect cleanup reverts it. Do not use `tl.call()` for state: it does not fire in reverse.
- `.box` must be at its resting CSS placement (`left`/`bottom`/`width` only) when `createFinale` runs; the `set` reads those as its from-values.
- Opacity lives on each `.shard`, never on `.box`: opacity < 1 on `.box` flattens its `preserve-3d`. Overlapping shards therefore blend with each other (accepted shift from the pre-finale logo).
- **Idle orbit** (`src/components/JnaoLogo/orbit.ts`, tuning constants `ORBIT`: seed, tilt, base turn, cycle turns, per-shard turn choices, ramp, float, z budget, layer gap, plate spins). `createOrbit()` returns a controller; `start()` (from `s = 0`, the flat logo) runs whenever the finale settles forward (including the silent seek when the page loads on the runway, and a resize rebuild while flying on the runway); `resume()` continues from the kept `s`, `pause()` holds the pose still engaged, `stop()` pauses and disengages, `measure()` rescales after a resize. Each frame an anime `createTimer` writes `translateX/Y/Z` and `rotateX/Y/Z` per shard with `utils.set` (anime's transform cache stays current). Pose: each shard moves as a rigid body, tidally locked — R = rotation by θ about the view axis tilted `tilt` towards the top, at a seeded `n ∈ shardTurns` whole turns per cycle (`cycle = cycleTurns × turn`), θ = 2π·n·s/cycle. Its centre `p0` (bbox centre − logo centre, scaled to the `.box` width) goes to R·p0 plus a seeded float height along the axis × sin²(π·s/cycle), and the shard turns by the same R about its own centre (the default `transform-origin`), so the same side always faces the centre and it is seen at an angle, edge-on or from behind. Plate shards (`*Plate` tones) first spin about their own seeded unit axis through their centre, at a seeded `m ∈ plateSpins` whole spins per cycle (φ = 2π·m·s/cycle, drawn from a second seeded random so the orbit's own sequence is unchanged); the total rotation is R·S(φ), so a plate tumbles while staying carried by its orbit. Whole spins keep the line-up exact. R is written as `eulerXYZ()` angles because anime emits rotations in the fixed order rotateX → rotateY → rotateZ (CSS rotation matrices are the standard ones in x right, y down, z towards the viewer, so they match `rotate()`'s Rodrigues maths). All θ are whole turns and the float is 0 at every cycle end, so every shard lands exactly in its logo pose (R = I, no translation) every cycle. z is never scaled (that would break the rigid motion): while orbiting, `.box`'s CSS `perspective` widens to max(`FINALE.perspective`, deepest centre |z| / `zBudget`), set inline by `orbit.ts` and restored to `FINALE.perspective` by `stop()`; `layerGap × index` keeps DOM paint order among coplanar shards. Orbit time `s` accumulates through a smoothstep speed ramp over `ramp` (so line-ups land `ramp/2` late), is wrapped to one cycle, and survives a resize (`measure()` rescales). While engaged (running, paused, and through the leave until the seam), `.box[data-orbit]` gets `transform-style: preserve-3d` (real front/back ordering); everywhere else stays flat in DOM order. Uses its own seeded random, so `FINALE`'s sequence is unaffected. Do not tween `perspective` on `.box` through anime: anime writes it as a `perspective()` transform, not the CSS property.

### BakersMathsLogo timeline
- Structure driven by data attributes: `g[data-stalk]` → paths with `data-type="stem"|"grain"|"whisk"`, grains ordered by `data-order`.
- Stems/grains: a stroke clone is drawn (`svg.createDrawable`) while the original's fill wipes bottom-to-top via a generated `clipPath` rect; the fill wipe ends when the outline does. Whisks: clip-wipe only.
- Randomised per run: easings, slot jitter, fill delay. Total ≈ `totalDuration` (6000ms); stalks overlap by `stalkOverlap`.
- `.drawing` class hides fill/stroke until animated; removed `onComplete`.

## Gotchas
- `logoanimated.module.scss` colours use `oklch(var(--color-logo-*))`; those vars are not defined in this repo, so the declarations are invalid at computed time and `fill`/`stroke` fall back to inherited — i.e. `.listLink` orange. Defining those vars will change the logo's colour.
- anime.js scopes select by global class string, not CSS-module class; the global class must be added alongside the module class (`classNames(styles.x, 'logo')`).
- `useAnimatedLogo` touches every `<path>` under the ref — non-animated paths must live outside that SVG.
- `HistoryScenes` must register its `popstate` listener before the App Router's (it does: child effects run first) and calls `stopImmediatePropagation`; if that order ever flips, back/forward swap without the scroll-to-top.
- Offsets inside the scroller are `main.scrollTop + rect.top - main.rect.top`; dropping the `scrollTop` term breaks on a second effect run (React strict mode).
